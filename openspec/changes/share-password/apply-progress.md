## Deviations from Design

Batch 1's 4 deviations (ShareLinkDO extends DurableObject; ArrayBuffer BLOB normalization; e2e worker exports; alarm hard-deletes) and Batch 2's 5 deviations (`shareStorage` param optional/trailing; RED-after-GREEN ordering slip on 4.2, corrected; hardcoded rate-limit thresholds; both IP- and share-scoped rate-limit keys enforced; `ShareStorage.peek()` never reflects `revoked`) carry forward unchanged — see the Batch 1/2 sections above for file pointers; full rationale is in git history (commits `99051537`, `bd8b5cc9`, `aafd0aba`, `8a4ffc43`).

Batch 3 deviations:

1. **The shared fragment-key util (`lib/share.ts`) was created directly during the 5.2/5.3 GREEN step, not duplicated inline in `share-dialog.ts`/`share-view.ts` first and extracted afterward in 5.5.** Tasks.md's literal phrasing frames 5.5 as a REFACTOR step ("shared fragment-key parsing util"), which normally implies removing real duplication. Deliberately writing the encode logic in the dialog and the decode logic in the view as duplicated one-liners, then extracting them, would have produced identical final code but with zero additional test signal — the RED test (5.2) already targets the shared module directly, so GREEN (5.3) necessarily created it there.
